الأوامر اليومية

هدول اللي بتستخدمهم كل يوم. والأول فيهم بيغنّي عن الباقي عادةً.

dotnet run -- todayreport بيستهلك نداءات

روتين الصباح كامل بأمر واحد — بيشغّل report وبعدها drafts وبعدها audit، لكل الأزواج.

إمتىكل صباح. وهو الأمر الوحيد اللي بتحتاجه عادةً.
النتيجةملفات reports/ + ملفات drafts/ + بطاقات التدقيق على الشاشة.
dotnet run -- report بيستهلك نداءات 5 ملفات لكل زوج

التقرير المؤسسي — السردي والأرقام الكمّية — لكل الأزواج المفعّلة.

إمتىلما بدك التقارير بس، بلا مسودّات ولا تدقيق.
النتيجة في reports/ لكل زوج: {الزوج}-{التاريخ}.json · -ar.txt · -en.txt · -cone.svg (رسمة مخروط الاحتمالات، جاهزة للدمج بالـ Word أو PDF) · -validation.json (نتيجة فحوص ما قبل النشر)
وكمانبيؤرشف القراءة كغير منشورة — بتصير مرجع «ما تغيّر» للمرّة الجاي، وبتفوت حلقة تقييم النتائج.
dotnet run -- report XAUUSD 1D بيستهلك نداءات

نفس التقرير بالضبط بس لزوج واحد محدّد — نفس الـ 5 ملفات.

إمتىلتحديث الذهب أو اليورو لحاله.
dotnet run -- drafts بيستهلك نداءات

مسودّات Substack إنجليزية لكل زوج.

النتيجةdrafts/{الزوج}.txt
dotnet run -- audit صفر نداءات بلا ملف

تدقيق جودة الأرقام — معايرة ذاتية، مش تقرير. وهو الأمر الوحيد اللي بيدقّق بدل ما ينتج.

إمتىللتأكد من مصداقية الأرقام مقابل الواقع.
النتيجةعلى الطرفية بس — أربع بطاقات (التفصيل تحت).

مش كل يوم. وكلهم بيقرأوا المخزّن — صفر نداءات للمزوّد.

dotnet run -- weeklyصفر نداءات

ملخّص أسبوعي مبني من التقارير المؤرشفة.

إمتىآخر الأسبوع.
النتيجةdrafts/weekly-ar.txt وweekly-en.txt
dotnet run -- publishsiteصفر نداءات

بيحوّل التقارير المنشورة لصفحات موقع.

النتيجةصفحات HTML في مجلد WebPublisher:OutputDirectory.

إمتىبعد audit أو backfill، لما تحدّث الموقع.
النتيجةcalibration.html

أوامر الإعداد

مرة وحدة، أو نادراً.

dotnet run -- seedhistoryبيستهلك نداءات

بيجيب كامل التاريخ اليومي وبيخزّنه — بيعمّق التاريخ المتاح للتحليل.

إمتىمرة عند الإعداد.
dotnet run -- backfillنداء لكل رمز

بيبني سجلّ VaR و ES من الماضي بمسح walk-forward.

إمتىمرة بعد seedhistory — بيفعّل بطاقات المعايرة، وخاصةً ES.
النتيجةبيخزّن النتائج اللي بتغذّي بطاقات audit.
dotnet run -- backupصفر نداءات

نسخة احتياطية موثَّقة من قاعدة البيانات، بعد التحقّق من سلامتها.

إمتىقبل أي أمر مدمّر — والبوت الحيّ بياخدها يومياً لحاله.
النتيجةbackups/quant-YYYYMMDD-HHmmss-fff.db
dotnet run -- purgeweekendمعاينة · ما بيحذف

معاينة شموع عطلة نهاية الأسبوع المخزّنة. ما بيحذف ولا إشي.

النتيجةجدول بالسلاسل وعدد الشموع المرشّحة للحذف.
dotnet run -- purgeweekend applyمدمّر

بيحذف تلك الشموع فعلياً.

إمتىبعد backup وبعد ما تراجع المعاينة.
نطاقهالسبت والأحد من السلاسل اليومية فقط — سلاسل الماكرو الشهرية ما بتتمسّ.

ليش في أمر بيحذف شموع أصلاً

تغذية GOLD_SILVER_HISTORY كانت بترجّع صفاً لكل يوم تقويمي — و26% منها سبت وأحد، وهاي مش جلسات تداول. الاستقبال صار يحذفها، والتاريخ المتراكم بينظَّف بهاد الأمر.

والأثر مقيس: VaR95 للذهب على النافذة الحيّة انتقل من 96.33 إلى 113.44 — بزيادة 17.8%. والفضة +17.9%. أما اليورو والجنيه والين وسندات العشر سنين فبلا تغيير، لأنها ما بتحمل شموع عطلة أصلاً.

الأسواق المدعومة

تلات رموز نشطة. والفرق بيناتهم شكل البيانات، مش المحرّك.

EURUSD

اليورو/دولار — فوركس · نقطة FX_DAILY · OHLC كامل (افتتاح، أعلى، أدنى، إغلاق) · الجودة كاملة

XAUUSD

الذهب/دولار · نقطة GOLD_SILVER_HISTORY · سعر واحد لليوم، بلا حركة داخل اليوم · الجودة FAIR

XAGUSD

الفضة/دولار · نفس التغذية وشكل البيانات · الجودة FAIR — ومعايرتها لسّه «العيّنة صغيرة»، لأن النتائج اللي بتقدر تقيّمها أقل

حدود المعادن — وهو حدّ بيانات مش حدّ محرّك

الباقة المجانية بترجّع سعراً واحداً لكل يوم (حوالي 5,300 شمعة رجوعاً لـ 2011)، بلا افتتاح وأعلى وأدنى منفصلين. والنتيجة:

  • بيشتغل منيح: الاتجاه، الزخم، المخاطرة (VaR)، الحالة، الدعم والمقاومة، خريطة السيولة، السياق التاريخي.
  • ضعيف أو فارغ: أنماط الشموع، جمع السيولة اللحظي، فجوات القيمة العادلة — لأنها كلها بتحتاج حركة داخل اليوم.
  • جودة السوق بتستقر عند FAIR وممكن تطلّع «لا قرار» أكتر من اليورو.

وseedhistory ما رح يرفعها — هاي شكل البيانات نفسها. رفع الجودة بيحتاج مزوّداً مدفوعاً بيعطي حركة داخل اليوم.

باختصار: dotnet run -- report XAUUSD 1D بيشتغل تماماً — بس توقّعاتك من المعادن تكون FAIR مش كاملة.

حصة مزوّد البيانات

الحصة المجانية 25 طلب باليوم، مع حدّ لحظي حوالي طلب بالثانية — بيتدار تلقائياً بمُباعدة النداءات.

بتستهلك نداءات

report · drafts · seedhistory · backfill (نداء واحد لكل رمز — بيجيب التاريخ الكامل وبعدين بيمسحه)

صفر نداءات

audit · weekly · publishsite · publishcalibration · backup · purgeweekend — كلها بتقرأ المخزّن بس

قدّيش بيكلّف التقرير؟ لا تخطّط على رقم محفوظ

report XAUUSD 1D انقاس بـ 5 نداءات — الزوج نفسه، ورفقاء الارتباط المتقاطع، وسلاسل الماكرو.

والرقم مش ثابت. بيتغيّر مع مُباعِد الجلب (الشموع اللي انجلبت قبل شوي ما بتنجلب تاني)، ومع الرفقاء المُعدّين، ومع كون التقويم الاقتصادي والتحليل الأساسي معطّلين حالياً.

أوامر report وdrafts وseedhistory و todayreport بتطبع بآخرها عدد نداءات هاي العملية. والعدّاد لكل عملية — كل تشغيلة بتبدأ من صفر، ما في تراكم يومي. وهو المرجع، مش هاي الصفحة.

بطاقات التدقيق الأربع

هاي اللي بيطبعها audit على الطرفية.

معايرة VaR

هل النطاق المتوقّع عند 95% بينخرق ~5% من الأيام زي ما لازم؟ وبيشمل اختبار تكتّل الخروقات — Christoffersen.

معايرة ES

في أيام الخرق، هل متوسط الخسارة الفعلية طابق الـ Expected Shortfall المُعلَن (النسبة حوالي 1)؟ بيظهر بعد ما يتراكم عدد كافٍ من أيام الخرق — بعد backfill أو بتراكم حيّ.

صمود المستويات

لما النظام يرصد مستوى مُختبَراً، كم مرة صمد فعلاً؟ مسح تاريخي بلا نظر مستقبلي.

ثبات الارتباطات

هل رقم ارتباط الـ 30 يوماً المنشور موثوق ولا متذبذب؟
